## 1. E1: extra 字段跨次上报是否持久 + 顶层 _redactions 是否被丢弃
POST /api/v1/traces  (session_id=audit-probe-l3b-extra)
  body1: extra={request_id,user_id:"510",failover_policy}, _redactions=2, turns=[turn_l3b_1]
  body2: turns=[turn_l3b_2]（不带 extra）
--> post1 201 / post2 201
POST1 响应：{"extra":{"failover_policy":"disabled","request_id":"legacy_request_id_abc",
             "user_id":"510"},"session_id":"audit-probe-l3b-extra"}
GET /api/v1/traces/{id} | jq '{extra, keys, turns, redactions}'
--> {"extra":null,
     "keys":["environment","eval_status","extra","project","release","reported_at_ms",
             "run_id","session_id","tags","thread_id","total_duration_ms",
             "total_input_tokens","total_output_tokens","turn_id","turns"],
     "turns":["turn_l3b_1","turn_l3b_2"],
     "redactions":null}
结论：extra 被第二次上报整体置 null；顶层 `_redactions` 因 typed struct 重序列化被静默丢弃。
代码锚点：crates/core/src/trace_merge.rs:13 (`let mut merged = new.clone()`),
          crates/server/src/routes.rs:1199-1200, crates/core/src/pg_repository.rs:665-677。

## 2. E2: 合并后单行是否可能超过 2MB（2MB 只是 POST body 限制）
POST 两次同 session（audit-probe-l3b-cap），每次 turns=[{blob:"A"*1,200,000}]
--> post1 201 / post2 201
select pg_column_size(payload), octet_length(payload::text)
  from traces where session_id='audit-probe-l3b-cap';
--> 27913 | 2400513        （JSONB 压缩后 27,913B，但 wire 文本 2,400,513B）
GET /api/v1/traces/{id}
--> 200 / size_download=2400913
GET /api/v1/traces?project=job_copilot&limit=100000
--> 200 / size_download=4414470
结论：body limit 只约束单次 POST；session 单行合并后可 >2MB，读接口无投影/无 clamp。
代码锚点：crates/server/src/routes.rs:422 (DefaultBodyLimit), pg_repository.rs:717-758。
