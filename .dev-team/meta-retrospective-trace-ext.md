# 元框架复盘：trace v2 扩展波（v1.5，收口剩余全部条目）

## 1. 通信拓扑与信噪比（Topology & Noise）

- 复用旧名册（protocol-scribe/auditor-core/auditor-diagnostic/executor-web/test-agent-2/verifier），Roster 仍 5 常驻；
  一次「角色漂移」复用（verifier → 生产者 executor）避免了跨仓另起团队。
- 最高信噪比：**core 先给 5 个接口签名、HTTP 侧按签名并行**，把「等待 core 落地」的串行段压到 ~10 分钟；
  代价是 HTTP 侧首轮报告「API 不存在」——属预期，靠 Lead 预定义签名解决。
- 噪声：① 任务板漏建 task-17..21，执行者只能按消息正文干活（事后补账本）；② 红相首次运行被实施者 cargo 锁阻塞 >10min，
  test-agent-2 改用快照二进制 `PONY_SENTRY_BIN` 解耦——这是可复用的好模式。

## 2. 门禁穿透与误杀率

- 红相 9/10 失败（1 条 GUARD-GREEN 防回归），绿相 10/10——红相发现 1 条**测试自身缺陷**（W-05 用断言 2xx 的 helper 测 400），
  Lead 修正后通过：说明「红相失败原因」也要审查，否则会把测试 bug 当能力缺失。
- 生产迁移用「新二进制随机端口启动一次」完成 schema+回填，未影响在跑旧服务；核验 0 不一致（38 traces → 59 turns）。
- PG 门禁固化为 `scripts/test-all.sh`（未设 `PONY_TEST_PG_URL` 直接 exit 2），消除「SKIP 即绿」的结构性假绿。

## 3. 分工契约与隔离有效性

- 契约 v1.5 把 13 条残项逐条落成可判定口径（含 `_` 前缀保留命名空间、`_unmapped` 注入时机、截断按字符、去重键），
  执行者无需二次决策；唯二需要裁决的点（`_` 前缀、input_text 能力面 vs 运行时）都由 Lead 一句裁定。
- 生产者侧在**另一仓库**且存在他人未提交改动：只按路径 add 4 个文件提交，未污染他人工作区；这是跨仓协作的可行模式。

## 4. 元协议迭代建议

1. **红相失败归因分类**：要求红相收据区分「能力缺失」与「测试缺陷」，测试缺陷须 Lead 裁决后再计数。
2. **跨仓任务**：任务卡必须写明「只 add 指定路径、禁止 commit 他人改动」，并在收据登记 commit sha。
3. **接口先行的并行**：Lead 在派发并行任务前，先发一版「接口签名清单」；执行者以此为准、发现漂移立即回报。
4. **任务板补记规则**：漏建任务应在收口前统一补记（本轮合并为 T11），避免多条僵尸 pending。
