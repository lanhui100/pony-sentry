## 三、口径与偏差（全部为客观事实，非裁量）

1. 渲染器：web/package.json 的 test 脚本是 `node --test tests/*.test.js`，未接线 vitest；
   vitest/jsdom 只作为传递依赖存在于 node_modules（不在 devDependencies），也没有 .vue 加载器。
   故 trace-ui.test.js 用 node:test，对 src/App.vue 做模板级 DOM 契约断言（不挂载组件）。
   若后续把 vitest 接线进 package.json，本文件可原地迁移为组件渲染断言（断言锚点不变）。
2. C9.8 保留期：黑盒可触发——`RETENTION_DAYS_TRACES=1` 下服务启动 30s 后执行首轮清理；
   用例用 python3 直连库文件把 A 行写成 created/updated 均 10 天前、B 行写成 created 10 天前但
   updated=现在，轮询 GET list 观测（无 SKIP、无硬编码 sleep 判据，超时上限 75s）。
   当前实现按 created_at 删除 → B 行被误删，断言真实失败（left: 0 / right: 1）。
3. C9.10 迁移回填：用 python3 执行 migrations/0001–0004 真实 SQL 构造「旧形态」库 + 仅含
   payload.turns 的存量行，再启动服务（启动即迁移），随后 GET 校验 turns_count/turn_status，
   并直连库查 trace_turns 行数与 seq 顺序。红相失败点：迁移回填后 turns_count 仍缺失。
4. C9.12（回归）：本文件不重复造轮子，由 `cargo test --workspace` + `web pnpm test` 全量覆盖。
5. 零脏数据：每用例独立临时目录 + 独立端口，Proc::drop 回收子进程与目录；未触生产库。
6. 已知契约空隙（需 Lead 裁决，未写入断言）：C2 未定义 per-turn token 字段名，
   本文件按 producer 现形态取 turns[].input_tokens/output_tokens/duration_ms（见
   docs/release/trace-audit-cards-2026-10-23/report.md:95-96）。
