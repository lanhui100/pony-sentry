## §1 改动点（routes.rs）

1. `IngestMetrics` 扩四个 `C7` 计数器（进程内、与既有 issue 计数同寿命；`BTreeMap` 保证 `/metrics` 稳定有序）：
   - `traces_total: Mutex<BTreeMap<(project, turn_status), u64>>`
   - `turns_total: Mutex<BTreeMap<status, u64>>`
   - `status_conflicts: AtomicU64`
   - `ingest_rejected: Mutex<BTreeMap<reason, u64>>`
   - 新增 `record_trace_ingested / record_trace_status_conflict / record_trace_ingest_rejected / trace_snapshot`
     （`trace_snapshot` 为 pub：`/metrics` 与服务的公开面；既有 `snapshot()` 签名不变）。
2. `handle_ingest_trace`：
   - 形参改 `Result<Json<AgentTraceIngestRequest>, JsonRejection>`：**先鉴权后解析**（401 优先于 422/415），
     非 413 的解析拒绝统一 400 `Bad request` 并计入 `ingest_rejected{reason="invalid_params"}`；
     413 保留 `Payload too large`（传输层限制，非上报语义错误）。
   - `session_id` 优先 / `thread_id` 回退，**空白也算缺失**；两者皆空 → 400 `Missing session_id or thread_id`
     并计入 `ingest_rejected{reason="session_missing"}`。
   - `TraceRecord` 补 `turn_status="unknown"` / `turns_count=0` / `note=None`（聚合列由 core 依据 turns 重算；
     `note` 仅 PATCH 写入）。
   - 成功路径：`record_trace` 返回**库内持久化行**直接作响应（`201` + Json(saved)，
     响应 `id` 可 GET、`total_*`/`turn_status`/`turns_count` 均来自 DB）。
   - DB 失败 → `tracing::error!` 记原文 + 响应体仅 `Internal error`（**不回显 DB 原文**）。
3. `TraceQuery` + `handle_list_traces`：
   - 新增 `run_id` / `turn_status` / `from` / `to`（后二者 RFC3339 → `DateTime<Utc>`）；
   - `limit`/`offset` 走自定义 deserializer（非数字 → 400）；handler 内负值 → 400；
     `limit` 其余值 `clamp(1,100)`（`limit=100000` → 100 行且 200）；未知参数按 serde 默认忽略；
   - `eval_status` 非法 → 400（错误文本自造，不含 DB/内部串）；repo 失败 → 500 `Internal error`。
4. `handle_update_trace`：改调 `update_trace_review(id, eval_status, note.as_deref())`（note 落库；None 保留旧值），
   404 语义不变，500 统一 `Internal error`。CSRF/会话分支未改动（`patch` 路由层逻辑保持原样）。
5. `handle_get_trace` / `handle_metrics`：DB 失败改为「日志原文 + 响应 `Internal error`」（顺带消除既有 500 泄漏面）。
6. `/metrics`：追加四个 `C7` 指标族（HELP/TYPE + label 值经既有 `escape_label` 转义，label 组合按 key 升序）。

## §2 指标触发语义（避免"计数正确但口径含糊"）

| 指标 | 触发点 | 累加语义 |
| :--- | :--- | :--- |
| `pony_sentry_traces_total{project,turn_status}` | ingest 成功（201） | 每次成功 ingest +1；label 取**持久化行**的 `project`（null → `unknown`）与 `turn_status` |
| `pony_sentry_trace_turns_total{status}` | ingest 成功（201） | 本次 `payload.turns` 逐条按 `trace_v2::turn_status_of` 归一后 +1（重报同一 turn 会再计一次 = 上报口径，非 DB 行数口径） |
| `pony_sentry_trace_status_conflicts_total` | ingest 成功且本次任一 turn 命中 `C4 status_conflict` | 每次 ingest 至多 +1（用 `trace_v2::annotate_turn` 在**入参副本**上判定，不污染入库数据、不依赖历史 diagnostics） |
| `pony_sentry_trace_ingest_rejected_total{reason}` | ingest 被拒 | `session_missing`（无/空白 session_id+thread_id）/ `invalid_params`（请求体解析拒绝，非 413） |

## §6 偏离与说明（须知会 Lead）

1. **`invalid_params` 从"声明"变为"真实触发"**：C7 给出 `invalid_params / session_missing` 两值，但 T3b 之后
   ingest 只有 session 缺失一种 400。本任务把「请求体解析拒绝（非 413）」映射为 400 + `invalid_params`，
   使 reason 词表有实际来源；顺带把「鉴权先于解析」修正（401 不再被 422 抢先）。
2. **413 未被并入 400**：`DefaultBodyLimit=2MB`（`routes.rs` 路由层）超限属传输层拒绝，保留 413 + `Payload too large`；
   若 Lead 要求严格「一律 400」，一行可改（会与 2MB 上限语义相悖，故默认保留）。
3. **`traces_total` / `turns_total` 是"上报口径"而非"库内行数口径"**：重复上报同一 session/turn 会再计数
   （与既有 `pony_sentry_ingest_requests_total` 的计数哲学一致）。HELP 文案已显式写入口径，避免将来误读为去重后的行数。
4. **`turn_status` / `turns_count` 入参占位**：`TraceRecord` 的这两列由 core 在写事务内依据 turns 重算，
   服务层传 `unknown/0` 仅满足结构体字面量；响应/库内值均来自 core 回查行（已在 §3-1 实证）。
5. **`/metrics` 的 DB 失败响应**由原文改为 `Internal error`（+ 日志原文）：顺带收敛 C5 的"任何 4xx/5xx 不得回显 DB 原文"要求，
   属既有面小修，不改指标集合。
6. **格式化**：`cargo fmt --check crates/server/{src/routes.rs,tests/api_test.rs}` 已单文件清零（全仓 57 处 fmt 漂移均在
   core 等其他写域，未触碰）。
