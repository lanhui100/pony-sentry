## 1) L3A-F4（MAJOR）retention 与 ingest 共用锁 —— CLOSED
实现（`crates/core/src/pg_repository.rs` `delete_traces_older_than`）：
  ① 快照 `SELECT id, session_id … WHERE COALESCE(updated_at,created_at) < $1 ORDER BY id ASC LIMIT $2`
     固定候选 id 集；
  ② 按 **id 升序**逐个 session 取 `pg_advisory_xact_lock(hashtextextended($session_id, 0))`
     —— 与 ingest 写入路径**同一把锁**；
  ③ 持锁后对每个 id 用 `SELECT 1 … WHERE id=$1 AND COALESCE(updated_at,created_at) < $2
     FOR UPDATE SKIP LOCKED` 复检过期性（等待期间若被 ingest 刷新为活跃行则跳过，不误删）；
  ④ 先按固定 session 集删 `trace_turns`，再按固定 id 集删 `traces`，同事务提交。
  ⚠️ 加锁序说明：行锁（`FOR UPDATE`）**放在 advisory 锁之后**。若按「先 FOR UPDATE 再 advisory」，
     retention(行锁→advisory) 与 ingest(advisory→行锁) 锁序相反，PG 会判定死锁并回滚其中一方
    （可能牺牲 ingest 请求）。现实现两侧统一「advisory → 行锁」，无环。
SQLite：`BEGIN IMMEDIATE` 全局写互斥，选择/删除同在单事务，无需额外锁（保持现状）。
用例（真实执行）：`pg::v2_pg_retention_and_ingest_interleaving_stays_consistent`（2 ingest × 6 round × 6 session
并发 vs 2 retention × 12 批）与 `v2_sqlite_retention_and_ingest_interleaving_stays_consistent`；断言
`turns_count == trace_turns 行数 == json(b)_array_length(payload.turns)` 且 0 孤儿。
实测输出：
  [L3A-F4] PG 交错后: 聚合行=6 轮次行=73 不一致行=0

## 2) L3A-F8（MINOR/OPEN）64 位 advisory 锁键 —— CLOSED
`pg_advisory_xact_lock(hashtextextended($1, 0))` 用于两处：ingest（`record_trace`）与 retention
（`delete_traces_older_than`），键空间由 2^-32 提升到 2^-64；注释说明两处必须同键否则不互斥。
`grep -n "pg_advisory_xact_lock" crates/core/src/pg_repository.rs` = 2 处，均为 `hashtextextended`。

## 5) L3B-F4（MAJOR PARTIAL）PG 迁移 DDL 拆分与锁控制 —— CLOSED
`crates/core/src/pg_repository.rs::migrate()` 不再 `raw_sql(整段 0005)`，改为
`ensure_trace_v2_schema()`（返回 `TraceSchemaReport`，pub 供测试断言）：
  - 迁移文件按 `;` 拆成**独立语句逐条 autocommit 执行**（先剔除 `--` 注释行）；
  - `ALTER TABLE … ADD COLUMN`：先查 `information_schema.columns`（当前 schema），**存在即跳过**
    → 二次启动不再对 `traces` 取 ACCESS EXCLUSIVE；
  - 5 个索引：先查 `pg_indexes`，缺失才用 `CREATE INDEX CONCURRENTLY`（**事务外**）；
    失败时 `DROP INDEX CONCURRENTLY IF EXISTS` 清理后**重试一次**并 `tracing::warn!` 记录；
  - `CREATE TABLE IF NOT EXISTS` 等幂等语句仍逐条执行（catalog no-op）；
  - down 迁移（`migrations/postgres/0005_trace_turns.down.sql`）保持不变且仍可用；SQLite 路径未改
    （`include_str!` + 列探测守卫，见 0005 头注释）。
实测（`pg::v2_pg_schema_ensure_is_idempotent_and_restart_light`，ponysentry_test 隔离 schema）：
